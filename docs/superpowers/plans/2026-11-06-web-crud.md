# GG Learn Web CRUD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Full role-checked create, read, update and delete on the web for courses, lessons, experiments, quizzes, questions, enrollments, badges and user accounts.

**Architecture:** React calls the Spring Boot API with the Firebase ID token. Spring Boot checks permissions in its services and reads and writes Firestore through the Admin SDK, using top-level collections where every child record carries `courseId`. The browser keeps reading only its own `users/{uid}` profile from Firestore.

**Tech Stack:** Spring Boot 4.1.2, Java 21, firebase-admin 9.9.0, JUnit 5, Mockito, AssertJ. React 19, Vite 8, Firebase JS 13 (auth only), Vitest.

**Spec:** `docs/superpowers/specs/2026-11-05-web-crud-design.md`. Read it before your task; the section numbers below (§) refer to it.

## Global Constraints

- **Java style:**
  - Tabs for indentation.
  - Records for DTOs, with jakarta validation messages written in friendly sentences.
  - Entities are plain classes with a no-arg constructor and `@DocumentId`.
  - Follow the existing style of `UserService` and `UserServiceTest`.
- **Errors:** throw `ApiException.badRequest`, `forbidden`, `notFound` or `conflict` from `com.gglearn.backend.exception`. Messages are short and child-friendly and use the curly apostrophe `’`, as the existing code does.
- **Every service method** takes `AuthUser me` first, starts with `userService.getProfile(me)` or `requireRole(...)`, and only then reads the target. (`getProfile` returns 403 for disabled users after Task 1.)
- **Firestore queries:** never combine `whereEqualTo` with `orderBy`, because that needs a composite index. Filter in Firestore and sort in Java.
- **Validation limits (§3):**

  | Field | Limit |
  |---|---|
  | Titles | 2 to 120 characters |
  | `content` | Up to 20,000 characters |
  | `materials` and `steps` | 1 to 30 items, each 1 to 300 characters |
  | `safetyNotes` | Up to 1,000 characters |
  | `gradeLevel` | Matches `K\|[1-6]` |
  | `topic` | Matches `life\|earth\|physical` |
  | `section` and `subject` | Up to 60 characters |
  | User `name` | 2 to 80 characters |
  | `password` | At least 6 characters |
  | `choices` | 2 to 6 items, each 1 to 200 characters |
  | `questionText` | 2 to 500 characters |

- **Front-end style:** 2-space indentation and ES modules, with no new runtime dependencies (only Vitest as a dev dependency). No emoji anywhere.
  - Reuse `Field`, `Confirm`, the existing CSS classes (`btn`, `small`, `plain`, `red`, `field`, `item`, `chip`, `alert`, `muted`, `wrap`) and the tokens in `src/styles/tokens.css`. New CSS goes in `src/styles/components.css`.
  - Every control is at least 48px tall. Any new animation is disabled under `prefers-reduced-motion`.
- **Every delete in the UI** goes through `Confirm`.
- **No router:** navigation uses `useNav().go({ name, ...params })`.
- **API base:** `import.meta.env.VITE_API_URL ?? 'http://localhost:8080/api'`.

## Review Focus

1. **Cascades over 500 documents.** Firestore batches cap at 500 writes, so deleting a big course must chunk its deletes. Pinned by `BatchesTest` (Task 1).
2. **A teacher demoted to student or pending_teacher** must lose edit rights to the courses they still "own". Role is checked before ownership. Pinned by `CourseServiceTest.demotedOwnerCannotUpdate` (Task 2).
3. **Padded or whitespace-only input** (`"  Seeds  "`, `"   "`) is trimmed or rejected, never stored padded. Pinned by `CourseServiceTest.createTrimsTitle` and `QuestionServiceTest.rejectsBlankChoiceAfterTrim` (Tasks 2 and 4).
4. **Duplicate choices** (`["Yes","Yes"]`) make the correct answer ambiguous and must be rejected with 400. Pinned by `QuestionServiceTest.rejectsDuplicateChoices` (Task 4).
5. **An expired token mid-session (401)** must sign the user out, not leave a broken page. Pinned by `api.test.js › calls the unauthorized handler on 401` (Task 8).
